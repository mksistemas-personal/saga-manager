# Skill: Creating and Adding an Entity

This skill describes the pattern and step-by-step guide to implement the use case for adding/creating a new entity in
the system, based on the functional architecture with `cyclops.control.Either` and conventions used in `AddSagaService`.

---

## 1. Structure and Prerequisites

Before creating the addition service, make sure that the following components exist or have been created:

1. **Request DTO (`<Entity>Request`)**:
    - Immutable record with the input data required for creation.
    - Validation annotations (`@NotBlank`, `@NotNull`, etc.), if applicable.

2. **Domain Entity (`<Entity>`)**:
    - Must extend `AbstractAuditable` (for auditing data such as `createdBy`, `createdAt`, etc.).
    - Must have Lombok's `@Builder`.
    - Must implement the `fillToCreate()` method for initialization and assignment of creation and auditing data.

3. **Repository Interface (`<Entity>Repository`)**:
    - Domain interface with the `save(<Entity> entity)` method.

---

## 2. Step-by-Step Service Implementation

### 2.1. Class Definition

- Class name: `Add<Entity>Service`.
- Location: module service package (e.g., `app.mkiniz.sagamanager.<domain>.services`).
- Visibility: **package-private** (no `public` modifier).
- Implements interface: `AddBusinessUseCase<<Entity>Request, <Entity>>`.
- Mandatory annotations:
    - `@Service`
    - `@Transactional`
    - `@AllArgsConstructor`
    - `@Validated`

### 2.2. Dependency Injection

- Declare repository as a `final` field (e.g., `private final <Entity>Repository <entity>Repository;`).
- Injection is performed via the constructor automatically generated by `@AllArgsConstructor`.

### 2.3. Internal Context Class (`Context`)

- Create a private static inner class `Context` to pass data between functional steps:
  ```java
  private static class Context {
      public <Entity> entity;
      public final <Entity>Request request;

      public Context(<Entity>Request request) {
          this.request = request;
      }
  }
  ```

### 2.4. Main Flow (`execute`)

- The `execute(@Valid <Entity>Request request)` method must orchestrate execution via the `Either` functional pipeline:
  ```java
  @Override
  public <Entity> execute(@Valid <Entity>Request request) {
      return (<Entity>) Either.<BusinessException, Context>right(new Context(request))
              .flatMap(this::create)
              .flatMap(this::save)
              .map(context -> context.entity)
              .fold(this::throwBusinessException, entity -> entity);
  }
  ```

### 2.5. Pipeline Methods

Each pipeline stage must receive `Context` and return `Either<? extends BusinessException, ? extends Context>`:

1. **Creation / Instantiation (`create`)**:
    - Constructs the domain object using `@Builder`.
    - Calls `context.entity.fillToCreate()`.
    - Returns `Either.right(context)` (or `Either.left(new BusinessException(...))` in case of an invalid business
      rule).
2. **Persistence (`save`)**:
    - Saves the entity in the repository (`<entity>Repository.save(context.entity)`).
    - Returns `Either.right(context)`.

## 3. Code Template

```java
package app.mkiniz.sagamanager.<domain>.services;

import app.mkiniz.sagamanager.<domain>.domain.<Entity>;
import app.mkiniz.sagamanager.<domain>.domain.<Entity>Repository;
import app.mkiniz.sagamanager.<domain>.domain.<Entity>Request;
import app.mkiniz.sagamanager.shared.business.AddBusinessUseCase;
import app.mkiniz.sagamanager.shared.business.BusinessException;
import cyclops.control.Either;
import jakarta.validation.Valid;
import lombok.AllArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.validation.annotation.Validated;

@Service
@Transactional
@AllArgsConstructor
@Validated
class Add<Entity>Service implements AddBusinessUseCase<<Entity>Request, <Entity>> {

    private final <Entity>Repository <entity>Repository;

    @Override
    public <Entity> execute(@Valid <Entity>Request request) {
        return (<Entity>) Either.<BusinessException, Context>right(new Context(request))
                .flatMap(this::create)
                .flatMap(this::save)
                .map(context -> context.entity)
                .fold(this::throwBusinessException, entity -> entity);
    }

    private Either<? extends BusinessException, ? extends Context> create(Context context) {
        context.entity = <Entity>.builder()
                .name(context.request.name())
                .description(context.request.description())
                .build();
        context.entity.fillToCreate();
        return Either.right(context);
    }

    private Either<? extends BusinessException, ? extends Context> save(Context context) {
        <entity>Repository.save(context.entity);
        return Either.right(context);
    }

    private static class Context {
        public <Entity> entity;
        public final <Entity>Request request;

        public Context(<Entity>Request request) {
            this.request = request;
        }
    }
}
```

## 4. Unit Tests

Create the test class `Add<Entity>ServiceTest` covering:

1. Successful creation with authenticated user in `SecurityContextHolder`.
2. Successful creation with default user (`system`) when unauthenticated.
3. Persistence validation on the repository mock (`verify(<entity>Repository).save(any(<Entity>.class))`).
